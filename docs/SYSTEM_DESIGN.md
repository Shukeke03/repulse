# RePulse 公开记录处理设计

版本0.2；2026年10月27日。此版本替代早期合成信号演示方案。

## 目标和边界

读取Mac项目目录中的公开人体记录，演示运动负荷结束后的脉率恢复观察。没有模型训练，也没有合成数据回退。原始文件、来源、许可和SHA256保留在项目数据目录；前端由同一FastAPI服务提供。

公开记录是Empatica E4的BVP与加速度，不冒充MAX30102 IR、连接中的手环或临床实时采集。STM32板级接口保留，但未上板的硬件能力不启用。

## 运行方式

| 方式 | 输入 | 算法与状态所有者 | 主机责任 |
| --- | --- | --- | --- |
| Python | 本地公开CSV | Python会话引擎 | 读取、处理、保存、推送 |
| FreeRTOS QEMU | 同一公开片段的受控二进制文件 | 固件采集/DSP/会话任务 | 验证、传输、保存、推送 |

来源始终为PUBLIC_DATA；执行方式与查看方式分别保存。显示历史处理回放时，不改变原记录来源。

## 会话与时间

CREATED→PREPARING→RECOVERING→FINALIZING→COMPLETED。取消进入CANCELLED；进程重启的未完成记录进入INTERRUPTED；无法处理或保存进入FAILED。

前10秒为源记录中恢复标记之前的历史。到达片段第10秒自动进入RECOVERING，恢复起点不可手动改写。到第134秒完成尾窗并保存。开始、取消命令检查revision，并以SQLite中的幂等键处理重试。

所有算法与回放使用记录时间。主机墙钟仅用于播放推进、连接和处理耗时。播放速度和浏览器冻结不改变窗口。

## 界面

1. 工作台：选择真实片段、处理方式、读取策略与播放速度。
2. 恢复过程：按源时间推进波形、质量、关键窗、变化量与腕端显示；明确这是一段录制数据。
3. 记录库：搜索、详情、备注、导出和批量删除。
4. 记录回放：独立时钟，从准备历史重建DSP，不显示尚未到达的窗口结果。
5. 策略比较：同一真实输入的三策略配对实验。
6. 数据与片段：下载文件、时间范围、阶段标记、来源、校验与预览。
7. 系统状态：实际服务、存储、时钟和FreeRTOS任务信息。
8. 设置：显示参数即时生效；默认策略用于下一次会话；固定参数明确显示为只读。

界面使用明确中文，不以口号、无解释缩写或不可操作的按钮代替功能。输入缺失、数据未下载、断线和无效结果均显示具体原因与可用恢复操作。

## 数据处理

采用原生64HzBVP与32HzACC。8秒窗、2秒重启预热、固定0/60/120秒窗口。详细计算与缺测规则见[ALGORITHM_CONTRACT.md](ALGORITHM_CONTRACT.md)。HR.csv仅为设备输出参考，不作为本系统算法结果或独立医学金标准。

## 接口

读操作：bootstrap、datasets及原始文件/样本、sessions详情/样本/事件、replays、comparisons、settings、system/status。

写操作：创建会话、开始/取消、备注、批量删除、创建/控制回放、策略比较/取消/导出、设置与记录导出。写操作携带Idempotency-Key。没有人工故障或合成场景接口。

实时通道为/api/live，回放通道为/api/replays/{id}/live。快照携带来源、执行方式、流ID、序号、记录时钟、阶段、窗口、数据尾段与诊断。快照不能代替原始文件归档。

## 保存与清理

默认所有文件位于项目data/内。原始下载放public/，运行结果放sessions/，QEMU受控传输文件放transports/，导出放exports/。用户可一次清理项目目录。

保存顺序为原始观测与事件→结果与SHA256清单→SQLite索引。备注与标签单独保存；回放不修改原文件。活动或被回放占用的记录整体拒绝删除。原始公开文件不随处理记录删除。

## 验证

验证真实文件与官方SHA一致、阶段标记映射、原生采样率、自动起点、固定窗口、缺测传播、原始文件不变、取消/中断保存、策略同输入、公用文件下载、所有页面与窄屏操作，以及实际QEMU的处理输出。

运行过的测试与未验证范围单独记在[VERIFICATION.md](VERIFICATION.md)，不将代码存在或编译成功写成实机验收通过。
